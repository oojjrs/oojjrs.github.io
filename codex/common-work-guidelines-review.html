01–07 범위와 권한

  1. 01

    시스템 및 개발자 지침을 따른 다음 사용자의 최신 요청을 따른다. 그 범위 안에서 이 문서를 가장 높은 우선순위의 공통 작업 지침으로 적용한다.

  2. 02

    명시적으로 요청된 범위 밖의 사용자 작업과 병렬 작업을 100% 보존한다. 알 수 없는 변경을 정리, 되돌리기, 덮어쓰기, 정규화, 이동, 삭제, 스테이징하거나 작업에 묶지 않는다. 안전하게 분리할 수 있는지 불확실하면 변경 전에 중단한다.

  3. 03

    이 규칙은 저장소, 코드, 문서, 애셋, Git, 검증, 유지보수 및 배포 작업에 적용한다. 일반 대화, 의견, 사실 질의응답, 번역 또는 재작성을 저장소 작업, 장기 목표나 실행 작업으로 전환하지 않는다. 요청에 답하는 데 필요하거나 대화 주제가 이 규칙 자체인 경우가 아니면 도구나 진행 상황 보고 없이 직접 답한다.

  4. 04

    검토, 진단, 설명, 계획 및 상태 요청은 읽기 전용이다. 조사하고 보고만 한다. 변경이나 수정 요청은 좁고 되돌릴 수 있는 로컬 편집을 허용하지만, 요청하지 않은 빌드, 테스트, 서버, 브라우저, 스테이징, 커밋, 배포 또는 외부 상태 변경은 허용하지 않는다.

  5. 05

    요청으로 승인된 일반적인 가역 작업은 중복 승인을 묻지 않고 수행한다. 결과를 실질적으로 바꾸는 결정이 빠졌거나, 안전하지 않은 작업 중첩이 있거나, 아래 규칙에 따라 별도 권한이 필요한 경우에만 중단한다.

  6. 06

    푸시, 배포, 영구 삭제, 강제 롤백, 파괴적 재작성, 유료 생성 또는 외부 레코드 변경은 사용자의 최신 메시지가 정확한 작업과 대상을 명시적으로 승인한 경우에만 실행한다. 과거 승인이나 상시 권한, 모든 것을 마무리하거나 처리하라는 포괄적 요청, 도구 또는 환경 권한은 승인으로 보지 않는다. 승인되지 않았다면 가역 작업까지만 준비하고 정확한 대상과 영향을 보고한 뒤 실행 전에 멈추어 질문한다.

  7. 07

    현재 요청이 해당 작업을 승인한 경우에만 명시적으로 요청된 범위를 스테이징하고 커밋한다. 푸시는 6번 규칙에 따라서만 수행한다.

08–09 스택과 근거

  1. 08

    확립된 프로젝트 스택을 존중한다. 기존 스택이 없는 독립 Windows 자동화 또는 웹 작업에서는 PowerShell과 .NET을 우선하고, 새 웹 작업은 ASP.NET 또는 ASP.NET Core를 기본으로 한다. 프로젝트가 이미 요구하지 않는 Unix, Linux, macOS 또는 POSIX 지향 도구, Node/npm/JavaScript 빌드 체인, 광범위한 오픈 소스 의존성 스택이나 Python은 사용자가 요청했거나 작업별 제약으로 우선 스택 사용이 불합리한 경우가 아니면 도입하지 않는다. 기존 예외는 유지보수 제약으로 취급하고 확장의 선례로 삼지 않는다.

  2. 09

    동작과 주장의 근거는 실제 코드, 애셋, 패키지 메타데이터, 기존 명세 또는 테스트, 외부 프로토콜 또는 스키마, 결과가 알려진 재현 버그와 사용자의 최신 결정에서 가져온다. 이러한 근거가 확립하지 않은 규칙, 요구사항, 설치 방법, 버전, 기능 주장 또는 예상 결과를 만들어내지 않는다. 빠진 선택이 결과를 바꾸는 경우 짧은 후보 목록과 함께 질문한다.

10–13 편집과 임시 파일

  1. 10

    변환을 요청하지 않는 한 기존 텍스트 파일마다 원래 인코딩과 줄바꿈을 정확히 보존한다. CRLF 확인은 CRLF 강제가 아니라 원본과의 일치 확인으로 취급한다. 새 텍스트 파일은 UTF-8 BOM 없음과 CRLF를 사용한다.

  2. 11

    마지막 편집 후 가능하면 실제로 수정한 텍스트 파일만 대상으로 공통 텍스트 형식 검사와 범위가 제한된 diff를 한 번에 실행한다. 커밋이 포함되면 최종 스테이징 검토가 일반 diff를 대신한다. 실제 불일치가 확인된 뒤에만 -Fix를 사용하며, 도구의 쓰기 후 검증이 반복 실행을 대신한다. 원본의 줄바꿈이 혼합된 파일은 수동으로 검토하고 자동 정규화하지 않는다.

  3. 12

    I/O와 컨텍스트 사용량을 작업에 비례시킨다. 검색 범위를 좁히고, 독립적인 읽기를 일괄 처리하고, 근거를 재사용하며, 광범위한 재검색이나 불필요한 산출물을 피한다. 생성 후보와 후처리 결과를 포함한 모든 필수 임시 또는 중간 파일은 프로젝트 루트 바로 아래의 리터럴 $Trash 디렉터리에 둔다. 임의의 tmp, temp, scratch 폴더나 다른 위치의 $Trash를 만들거나 사용하지 않는다. 먼저 프로젝트 루트를 확인하며, 루트가 불분명하거나 사용할 수 없으면 다른 위치로 대체하지 말고 중단한다.

  4. 13

    Unity UI 애셋을 만들거나 크기를 추천하기 전에 대상 프로젝트의 실제 Canvas 크기와 해당하는 Canvas Scaler 기준 해상도를 확인한다. 그 배율에서 예정된 배치를 평가하고 해당 값에 따라 크기를 정한다. 확인할 수 없다면 FHD, QHD 또는 4K라고 가정하지 말고 질문한다.

14–15 공개 문서

  1. 14

    공개 사이트 문서를 추가, 이동 또는 발행할 때 사이트의 기존 루트 내비게이션, 색인 또는 문서 목록에서 클릭해 도달할 수 있는 경로를 제공하고, 발행 시 렌더링되거나 배포된 전체 경로를 확인한다. 직접 URL이나 목적지 응답 성공만으로는 충분하지 않다.

  2. 15

    사용자가 다른 언어를 요청했거나 산출물에 보존해야 할 기존 언어가 있는 경우가 아니면 보고, 피드백 및 사용자 대상 문서를 한국어로 작성한다.

16–17 검증

  1. 16

    검증은 작업에 비례하고 중복되지 않아야 하며 독립적인 판정 근거를 사용해야 한다. 25% 비례 목표, 에이전트 제어 시간 15초 상한 및 반복 금지를 포함한 validation-guideline.md를 따른다. 목표 시간이 더 짧더라도 필수 형식 및 범위 diff 일괄 검사를 시작한다. 상한 안에서 이미 시작한 검사가 끝나도록 둔 다음, 재시도나 대체 검사 없이 중단한다.

  2. 17

    사용자가 해당 활동을 요청했거나 명시적인 빌드, 테스트, 런타임 진단 또는 렌더링 검증 작업에 본질적으로 필요한 경우가 아니면 빌드, 테스트, 서버 또는 브라우저 시작이나 테스트 생성을 하지 않는다. 같은 추측에서 만든 테스트와 구현은 서로의 정확성을 입증할 수 없다.

18–20 워크플로와 Git

  1. 18

    겹치지 않는 최소 워크플로를 로드한다. $oojjrs-project-start-work는 승인된 첫 로컬 파일 또는 Git 인덱스 변경 직전에만 사용하고, 한 번에 가장 구체적인 주 도메인 하나만 사용하며, 보조 스킬은 정확한 발동 조건에서만 추가한다. $oojjrs-project-finish-work는 요청된 스테이징, 커밋, 푸시, 배포, 릴리스 또는 Git 완료에만 사용하며, 일반 편집 후 자동으로 사용하거나 작업 시작 시 미리 로드하지 않는다.

  2. 19

    $oojjrs-github-project-board는 보드 작업이 요청됐거나 저비용 확인으로 이 작업에서 갱신해야 하는 관련 1:1 연결 보드가 확인된 경우에만 사용한다. $oojjrs-dirty-worktree-scope-split은 단지 작업 트리가 더럽다는 이유가 아니라 변경 조각이 겹치거나 안전한 분리가 실제로 모호한 경우에만 사용한다.

  3. 20

    기존 작업을 분리하는 데 필요할 때 저장소 상태를 최대 한 번 확인하고, 변경되지 않은 상태, 이력, diff 또는 스테이징 내용을 반복 확인하지 않는다. 승인된 커밋에서는 정확한 경로만 스테이징하고 최종 git diff --cached --name-status, 스테이징 diff 및 git diff --cached --check를 한 번 검토한다. 스테이징된 바이트가 바뀌지 않는 동안 그 검토 결과를 재사용한다.

21–23 정책과 보고

  1. 21

    재사용 가능한 정책은 이 정식 문서, 연결된 공개 지침 또는 좁은 조건에서 발동하는 단일 스킬에 둔다. 메모리는 진행 중인 임시 상태나 조사 위치의 단서로만 취급하고 지속적인 권위로 사용하지 않는다. 재사용 가능한 작업 지침이 메모리에만 있다면 권위로 사용하지 말고, 의존하기 전에 승인된 지속 가능한 위치로 옮긴다.

  2. 22

    사용자가 명시적으로 예외를 허용하지 않는 한 $oojjrs-guidelines를 가리키는 포인터 외에 저장소 로컬 AGENTS.md, HANDOFF.md 또는 유사한 지침 파일을 추가하지 않는다.

  3. 23

    변경 범위, 검사와 결과, 의미 있는 미검증 위험, 요청된 커밋, 푸시, 배포 또는 발행 결과를 작업에 비례해 보고한다. 관련 Git 이력은 결정에 영향을 주거나 사용자가 요청한 경우에만 포함한다. 작업에 적용되지 않는 관문, 일상적인 생략 사유, 변경되지 않은 이력 및 작업에 영향을 주지 않는 무관한 변경은 보고하지 않는다.
