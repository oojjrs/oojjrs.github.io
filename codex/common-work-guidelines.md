# Codex Work Rules

Canonical URL: `https://oojjrs.github.io/codex/common-work-guidelines.md`

This URL is the only authoritative runtime source. Read it once at the start of each actual-work thread or subagent. Do not re-read it before every command or tool call. Reload only in a new thread or subagent, after context restoration, or when the user explicitly asks. Repository and cached copies are never runtime substitutes.

1. Follow system and developer instructions, then the latest user request. Within that scope, apply this document as the highest-priority shared project guidance.
2. Use these rules for repository, code, document, asset, Git, validation, or deployment work. Ordinary conversation, factual Q&A, translation, and rewriting do not need this workflow unless the user asks about the rules themselves.
3. Review, diagnosis, explanation, planning, and status requests are read-only: inspect and report without editing files, staging, running builds or tests, starting servers or browsers, or changing external state unless the current request explicitly targets that activity. A change or fix request by itself authorizes only reversible local edits within the requested scope. Commit, push, deploy, release, and other Git or publication completion actions require authorization explicit in the current request; each authorization applies once to the exact scope and target covered by that request, expires when the authorized action completes, and does not carry to later changes or messages. When the current request does not authorize such an action, do not ask for or suggest authorization; complete only the already authorized scope and report it. Permanent deletion, forced rollback, destructive rewrite, paid generation, and external record changes likewise require explicit current-request authorization; do not infer it from an earlier request.
4. Preserve unrelated user and parallel-task changes. Keep the requested scope narrow and never clean, revert, normalize, stage, commit, or otherwise bundle unknown work.
5. Respect the existing project stack. For new standalone Windows automation or web work with no established stack, prefer PowerShell and .NET; do not expand a legacy or rejected stack without a task-specific reason.
6. Preserve each existing text file's encoding and line endings unless conversion is requested. New text files use UTF-8 without BOM and CRLF.
7. Load and follow `https://oojjrs.github.io/codex/validation-guideline.md` once, immediately before the first validation step, only when a task changes files or external state or explicitly requests validation. Do not load it for other read-only work.
8. Keep disk I/O and context proportional to the task: use targeted searches, batch independent reads, reuse unchanged evidence, and avoid rescanning unchanged state. Put necessary temporary and intermediate files under a literal `$Trash` directory.
9. Load only the smallest non-overlapping set of applicable workflows. Follow their documented triggers and precedence, and let the most-specific domain own subordinate rules.
10. Report proportionally in Korean: include applicable findings or changed scope, checks actually run and their results, meaningful unverified risks, and requested Git, deployment, or external-update outcomes; omit inapplicable, unchanged, or unrelated detail.
11. Do not add repository instruction files beyond a pointer to `$oojjrs-guidelines` unless the user explicitly requests an exception.
