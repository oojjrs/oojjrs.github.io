# oojjrs Unity C# Convention Maintenance

Before creating or editing any document or HTML file, read and follow `https://oojjrs.github.io/codex/document-writing-guideline.md`. Its text-addition approval rule takes precedence over this skill's writing, content, and synchronization instructions. Document/page creation, code changes, synchronization, translation, and publication do not approve text. Require separate prior approval of exact new or replacement wording and placement, including headings, table columns, examples, translations, and generated output. Assume 99% refusal: ask only when omission makes the requested result impossible; otherwise omit without asking. Present indispensable wording, placement, and reason in chat and wait for explicit approval; never prefill drafts or placeholders.

Treat the Unity C# convention as one document set:

- `codex/unity-csharp-coding-convention.md`: concise agent-facing copy containing every rule and decision criterion

## Workflow

1. Inspect every representation before editing.
2. Synchronize all applicable representations using separately approved exact wording for each language and location. Consistency does not authorize translating or filling missing text. Obtain any indispensable wording approval before publication; never publish an incomplete language or copy set.
3. Keep approved rule order, numbering, meaning, decision criteria, and correct/incorrect examples aligned; do not invent new examples or translations merely to fill a representation. The concise Codex copy may omit long examples but must not omit or weaken a rule.
4. Preserve each file's encoding and line endings while editing.
5. Compare rule inventories across all representations, and validate HTML structure only when an HTML representation changed.
6. Report a redirect problem or publication delay only when one actually affects the result.
