# 본·메시 리깅 제작 절차

본·메시를 새로 만들거나 고칠 때 이 문서를 읽고 해당 구간에 적용한다. 직접 작화만 필요한 구간에는 리깅을 강제하지 않는다.

## 1. 도구와 기준 좌표 확정

- 사용할 편집기·가져오기/내보내기 경로·공식 런타임과 버전을 먼저 확인한다. Spine의 메시와 IK는 해당 기능을 지원하는 에디션이 필요하다. [메시](https://esotericsoftware.com/spine-meshes) · [IK](https://esotericsoftware.com/spine-ik-constraints)
- 지원되는 원본 형식·API·가져오기와 CLI를 사용한다. 직접 데이터를 구성하면 대상 버전의 [JSON 형식](https://esotericsoftware.com/spine-json-format)을 따르고 공식 런타임으로 읽어 확인한다. `.spine` 파일을 임의로 흉내 내지 않는다. [CLI](https://esotericsoftware.com/spine-command-line-interface)
- 도구가 없으면 사용할 수 있는 제작 경로를 선택하고 검증 범위를 정확히 보고한다. 자체 렌더만으로 Spine 가져오기·런타임 호환 검증을 대신하지 않는다.
- 원본 캔버스 크기, 바닥 기준점, 출력 배율, 바라보는 방향, 키 포즈와 동작 범위를 고정한다. 잘라낸 파츠의 크기를 기준으로 캐릭터 전체를 다시 맞추지 않는다.
- 원본 이미지 좌표는 오른쪽 `u`, 아래쪽 `v`로 기록한다. 리그가 오른쪽 `x`, 위쪽 `y`를 사용하고 기준점이 `(u0, v0)`이면 `x = u - u0`, `y = v0 - v`로 한 번 변환한다. 엔진이 다른 좌표계를 쓰면 그 계약에 맞춰 변환한다.

## 2. 파츠 명세와 완전한 원화 준비

동작과 가림을 기준으로 필요한 부위를 열거하고 다음 정보를 각 파츠의 리그 데이터에 연결한다. 아래 표는 데이터 항목 설명이며 Markdown·HTML 명세서나 설명문을 만들라는 지시가 아니다. 문서에 넣을 새 문구나 교체 문구는 공통 문서 작성 지침에 따라 정확한 문구와 위치를 별도로 사전 허가받는다. 허가는 99% 거절된다고 전제하고 반드시 필요한 경우에만 먼저 물으며 나머지는 질문 없이 생략한다. 작업 자료는 프로젝트의 `$Trash`에서 관리하고 필요한 최종 원본만 결과물에 포함한다.

| 항목 | 기록할 내용 |
|---|---|
| 원화 | 파츠 ID와 레이어/PNG 경로, 대응하는 키 포즈·시점 |
| 배치 | 원본 캔버스에서의 위치, 잘랐다면 사각형과 오프셋 |
| 구조 | 부모 본, 회전 중심, 관절 끝점, 길이·두께 기준 |
| 변형 | 강체/유연체, 움직임 범위, 고정할 영역 |
| 표시 | 슬롯·어태치먼트, 앞뒤 순서, 필요한 가림·교체 그림 |

1. 몸통·머리·팔/다리·날개·귀·잎·눈자루처럼 독립적으로 움직이는 영역을 별도 레이어로 만든다. 관절이 둘이면 해당 관절을 각각 제어할 수 있게 나눈다.
2. 연속해서 휘는 잎이나 귀는 부위 원화를 유지하면서 내부 메시로 구부린다. 무조건 작은 강체 조각으로 잘게 자르지 않는다.
3. 가려져 있던 관절 끝, 밑면, 반대쪽 가장자리까지 완성한다. 파츠가 떠난 자리의 몸통·둥지·배경 면도 별도 원화로 복원한다. 필요한 경우 모든 파츠를 새로 그린다.
4. 파츠를 회전시켜도 틈이 생기지 않도록 관절 주변에 겹침을 준다. 검은 외곽선이 이중으로 보이면 겹침이나 안쪽 선을 수정하고, 흐림으로 숨기지 않는다.
5. 고정된 앞쪽 테두리·돌·털 등을 별도 가림 레이어로 둔다. 움직이는 파츠에 주변 고정 픽셀이 섞이지 않게 분리한다.
6. 모든 파츠를 기준 좌표에 다시 조립해 원본과 겹쳐 본다. 중립 자세부터 크기·윤곽·색·조명·접합부가 맞아야 한다.

PNG를 트리밍해도 원래 위치 오프셋을 보존한다. 여러 파츠가 텍스처 아틀라스 한 장에 들어가는 것은 허용하지만, 서로 다른 레이어·슬롯·어태치먼트로 제어할 수 있어야 한다.

## 3. 본 계층과 피벗 구성

다음은 구조 예시이며 실제 생김새와 동작에 맞춰 필요한 가지를 선택한다.

```text
root                         캔버스 기준점
├─ motion                    캐릭터의 의도한 이동
│  └─ body                   몸통 중심
│     ├─ head                목 접점
│     │  ├─ ear_l_base → ear_l_mid → ear_l_tip
│     │  └─ ear_r_base → ear_r_mid → ear_r_tip
│     ├─ arm_l_upper → arm_l_lower → hand_l
│     ├─ arm_r_upper → arm_r_lower → hand_r
│     ├─ leg_l_upper → leg_l_lower → foot_l
│     └─ leg_r_upper → leg_r_lower → foot_r
├─ foot_target_l             접지 제어가 필요할 때
└─ foot_target_r
```

- `root`는 캔버스 정렬, `motion`은 이동, `body`는 몸의 동작을 담당하게 분리한다. 제자리 동작에서 몸통 호흡 때문에 바닥 기준점까지 흔들리지 않게 한다.
- 회전 중심은 파츠 그림의 중앙이 아니라 실제 접점에 둔다. 팔은 어깨·팔꿈치, 귀는 머리와 만나는 밑동, 알돌은 둥지에 닿아 기우는 지점이 기준이다.
- 각 본의 축을 다음 관절 방향으로 맞추고 길이를 그 관절까지 정한다. 강체의 크기·길이를 바꾸지 않으며, 늘어남이 필요한 유연체는 의도한 범위 안에서 별도 제어한다.
- 부모 회전·크기·반사를 자식이 어떻게 상속하는지 확인한다. 부모의 비균일 확대가 손·눈·돌까지 찌그러뜨리면 계층이나 상속 설정을 수정한다. [본과 변환 상속](https://esotericsoftware.com/spine-bones)
- 본 개수는 목표 곡률과 관절 수로 정한다. 휘는 지점을 표현하지 못하면 본을 추가하고, 이미 표현되는 구간에 이름만 다른 본을 늘리지 않는다.

### 좌표와 바인드 포즈 예제

1024×1024 이미지의 기준점을 `(512, 900)`으로 두고, 수직 잎의 밑동·중간·끝을 다음과 같이 잡는다.

| 지점 | 이미지 좌표 `(u, v)` | 리그 기준 좌표 `(x, y)` |
|---|---|---|
| 밑동 | `(512, 500)` | `(0, 400)` |
| 중간 | `(512, 350)` | `(0, 550)` |
| 끝 | `(512, 200)` | `(0, 700)` |

- 첫 본은 `(0, 400)`에서 위쪽을 향하게 회전 90도·길이 150으로 둔다.
- 둘째 본은 첫 본의 자식이며 **부모 로컬 좌표 `(150, 0)`**, 로컬 회전 0도·길이 150이다. 부모가 이미 위쪽을 향하므로 `(0, 150)`을 넣으면 잘못된 위치가 된다.
- 부모가 회전·확대된 일반적인 경우 자식의 월드 위치에서 부모 위치를 빼기만 하면 안 된다. 부모의 전역 행렬을 역변환해 자식 로컬 변환을 구한다.
- 기준 자세에서 모든 파츠가 다시 원화 위치에 놓이는 상태를 바인드 포즈로 저장한다. 애니메이션 자세를 시험하면서 바인드 포즈를 덮어쓰지 않는다.

자체 제작 도구에서 열벡터를 사용하는 경우, 본의 전역 행렬은 `G = G_parent × T × R × S`로 구성한다. 기준 행렬 `G_bind`와 현재 행렬 `G(t)`를 구분한다. 메시 정점 `p`의 변형은 다음 관계를 만족해야 한다.

```text
v_i = inverse(G_bind_i) × p
p(t) = Σ_i weight_i × G_i(t) × v_i
Σ_i weight_i = 1
```

원본 정점에 현재 행렬만 곱하거나 부모 변환을 두 번 적용하면 파츠가 튄다. 실제 엔진/API의 행렬·좌표 규약에 맞춰 적용하고 중립 자세와 단일 본 회전으로 확인한다.

## 4. 어태치먼트와 메시 생성

- 단단한 파츠는 한 본에 붙인 region 어태치먼트나 단일 본 가중치 메시로 시작한다. 유연한 파츠에는 그 파츠만 덮는 메시를 만든다.
- 파츠의 실루엣을 자르지 않도록 외곽 정점을 놓고, 굽힘 관절과 큰 곡률 변화 주변에는 내부 정점·가로 단면을 추가한다. 큰 삼각형 하나가 굽는 부위를 가로질러 버티지 않도록 연결한다. [메시 정점 배치](https://esotericsoftware.com/spine-meshes#Vertex-placement)
- 눈·보석·돌 표면처럼 강체로 유지할 영역은 별도 파츠로 분리하거나 같은 본의 영향을 받게 한다. 외곽선과 하이라이트가 늘어나는지 최대 자세에서 확인한다.
- 캐릭터 전체 이미지에 균일한 격자만 씌워 독립된 파츠·관절을 대신하지 않는다. 필요한 부위 안에서 형태와 변형을 설명할 수 있는 메시를 만든다.
- 자동 생성 메시를 그대로 확정하지 않는다. 잘못 연결된 삼각형·빈 영역·급격한 굽힘을 확인하고 정점이나 내부 연결선을 고친다.
- 이후 메시 구조를 바꾸면 가중치와 기존 변형 키도 다시 확인한다. 바인드가 끝난 메시를 리셋해 기존 작업을 잃지 않게 한다.

## 5. 바인딩과 가중치 수정

[Spine 가중치](https://esotericsoftware.com/spine-weights)는 각 정점이 어느 본의 변형을 얼마나 받는지 정한다. 자동 계산은 출발점이며 최종 결과는 동작 범위에서 수동으로 고친다.

1. 해당 파츠를 움직일 본만 바인딩한다. 귀 메시를 옆 귀나 몸통의 무관한 제어 본에 연결하지 않는다.
2. 강체 영역은 담당 본에 가중치 1을 주고 나머지는 0으로 둔다. 접지한 밑동은 고정 기준 본에 묶어 위쪽 굽힘의 영향을 받지 않게 한다.
3. 유연한 관절은 인접 본 사이에 가중치를 점진적으로 나눈다. 두 본의 시작 예시는 다음과 같으며, 실제 두께·길이·곡률에 맞춰 조정한다.

| 영역 | 이전 본 | 다음 본 |
|---|---|---|
| 앞쪽 고정 구간 | 1.0 | 0.0 |
| 관절 앞 | 0.75 | 0.25 |
| 관절 중심 | 0.5 | 0.5 |
| 관절 뒤 | 0.25 | 0.75 |
| 뒤쪽 구간 | 0.0 | 1.0 |

4. 모든 정점의 가중치는 유효한 본을 가리키고 합이 1이 되게 한다. 의도하지 않은 작은 가중치를 제거하고 고정 영역으로 번진 영향도 지운다.
5. 수정할 정점과 본만 선택해 자동 계산·평활화를 적용한다. 전체 자동 계산으로 확정한 손·눈·밑동의 가중치를 다시 망가뜨리지 않는다.
6. 한 본씩 필요한 최대·최소 각도로 움직이고 나머지 제어는 고정해 영향을 확인한다. 이어서 실제 키 포즈들의 조합에서도 관절의 틈·부피 감소·외곽선 늘어남을 확인한다.
7. 가중치만으로 형태가 유지되지 않으면 메시·파츠·피벗을 고치거나 보정 그림을 추가한다. 돌을 말랑하게 만들어 회전을 흉내 내지 않는다.

## 6. FK·IK와 접지 선택

- 귀·잎·꼬리처럼 밑동부터 끝으로 전달되는 움직임은 FK로 각 관절을 제어한다. 밑동이 먼저 움직이고 끝부분이 뒤따르도록 타이밍을 달리한다.
- 손·발이 특정 점을 유지해야 하면 해당 접점을 목표로 IK를 사용하거나 FK 키로 접점을 유지한다. Spine IK는 한 본 또는 두 본 체인을 지원하므로 긴 체인에 단일 IK를 임의로 적용하지 않는다. [IK 구성과 제한](https://esotericsoftware.com/spine-ik-constraints)
- IK 목표 본은 제어하는 관절 체인의 자손으로 두지 않는다. 몸통의 위아래 움직임이 목표점까지 함께 끌고 가지 않도록 접지에 맞는 기준 공간에 둔다.
- 무릎·팔꿈치의 굽힘 방향을 명시하고, 도달 범위 경계에서 갑자기 뒤집히는지 확인한다. 강체 팔다리의 자동 늘이기는 의도한 연출이 있을 때만 사용한다.
- 발이 붙는 구간에는 접점이 같은 공간의 같은 점을 유지해야 한다. 들리는 구간에는 의도한 궤적을 허용한다. 모든 프레임을 바닥에 맞춰 공중 동작을 지우지 않는다.
- 게임에서 캐릭터 이동을 별도로 적용한다면 제자리 보행·발 접촉 타이밍과 실제 이동 속도 계약도 맞춘다.

## 7. 슬롯·앞뒤 순서·가림 구성

Spine의 본은 변환 계층이며, 이미지 표시는 본에 연결된 슬롯과 그 아래 어태치먼트가 담당한다. 슬롯의 그리기 순서로 앞뒤를 정한다. [슬롯](https://esotericsoftware.com/spine-slots)

- 뒷다리·뒤 날개 → 몸통 → 머리 → 앞다리·앞 날개 → 표정처럼 기준 자세의 순서를 정하고, 실제 겹침에 맞게 키를 준다.
- 표정이나 시점을 교체할 때는 해당 슬롯의 어태치먼트를 바꾼다. 이전 눈·입·날개가 남아 이중으로 보이지 않게 한다.
- 몸 뒤에서 앞으로 넘어오는 파츠는 필요한 순간의 순서 변경과 전후 포즈를 함께 설계한다. 순서만 뒤집어 잘못된 실루엣을 숨기지 않는다.
- 둥지 앞 테두리처럼 항상 앞에 있어야 하는 파츠는 고정 가림으로 둔다. 클리핑을 쓰면 시작 위치와 끝 슬롯을 지정하고 다른 파츠까지 잘리지 않는지 확인한다. [클리핑과 그리기 순서](https://esotericsoftware.com/spine-clipping)
- 텍스처 잘림·투명 테두리·색 번짐은 원화, 크롭, 메시 외곽, UV, 아틀라스 여백, 알파 처리 중 어느 단계에서 생겼는지 나눠 확인한다.

## 8. 새 키 그림과 구간별 리그 연결

1. 기존 리그가 다음 시점·형태에 맞지 않으면 그 구간용 리그를 새로 만든다.
2. 구간마다 동일한 캔버스·기준점·출력 배율을 쓴다. 시작·종료 키 포즈를 기준으로 관절·윤곽·색·가림 위치를 맞춘다.
3. 리그로 만드는 구간은 자세·회전·위치·필요한 변형을 키로 만들고, 움직임 간격과 속도 곡선을 설계한다. 보간 프레임 수를 늘리는 것만으로 타이밍이 좋아졌다고 판단하지 않는다.
4. 서로 다른 파츠 수나 구조의 리그를 억지로 보간하지 않는다. 새 그림·어태치먼트 교체·직접 그린 연결 프레임으로 이어 준다. 캐릭터·파츠의 포즈를 페이드인·페이드아웃·크로스페이드·시간 가중 알파 혼합으로 이어 붙이지 않는다. 광원·발광 등 효과용 불투명도 애니메이션은 허용한다.
5. 최종 프레임을 같은 좌표계로 렌더링해 연결한다. 경계가 튀면 해당 원화나 연결 포즈를 다시 그리고, 필요하면 그 구간 또는 전 프레임을 재작화한다.

## 9. 동작 분리 점검과 수정 순서

| 증상 | 먼저 분리해서 확인 | 수정할 대상 |
|---|---|---|
| 중립 자세부터 파츠가 튐 | 원본 배치와 바인드 자세 겹침 | 크롭 오프셋·좌표축·부모 역변환·바인드 행렬 |
| 몸통이 무관한 동작에 끌림 | 문제 본 하나만 회전 | 잘못된 바인딩·미세 가중치·부모 상속 |
| 관절이 찢어짐 | 최대 자세에서 앞뒤 파츠 단독 표시 | 숨은 원화·겹침·피벗·메시·가중치 |
| 단단한 부위가 말랑해짐 | 해당 영역의 영향 본 표시 | 단일 본 강체 바인딩·부모 확대·파츠 분리 |
| 잎이 각지거나 접힘 | 메시 선과 최대 굽힘 표시 | 정점 배치·삼각형 연결·본 수·가중치 |
| 다리가 뒤집히거나 발이 미끄러짐 | 목표점과 접촉 구간 표시 | IK 방향·목표 공간·도달 범위·이동 타이밍 |
| 리그 교체 순간 커졌다 작아짐 | 경계 프레임 원본 해상도 겹침 | 출력 배율·피벗·원화 비율·연결 포즈 |
| 잔상·이중 외곽선이 생김 | 합성 전 원본 프레임과 출력 비교 | 중복 어태치먼트·블렌딩·알파·인코딩 |

중립 재조립 → 단일 본 회전 → 필요한 극단 자세 → 전체 동작 → 구간·루프 경계 → 최종 출력 순서로 확인한다. 실패한 단계의 원화·구조·수치를 고친 후 그 영향 범위를 다시 본다.

## 10. 전달과 완료 기준

- 사용한 레이어/파츠, 기준 위치·피벗 자료, 본 계층, 메시·가중치, 슬롯·가림, 애니메이션 키와 소스 원화를 편집 가능한 상태로 보존한다.
- Spine 결과물을 납품하거나 호환성을 주장하면 대상 편집기 또는 공식 런타임에서 실제 로드·재생을 확인한다. 최종 데이터의 에디터/런타임 버전을 맞춘다. [내보내기](https://esotericsoftware.com/spine-export)
- 프레임 출력은 모든 구간에 동일한 기준 좌표·배율을 적용하고, 최종 PNG/WebP/시트에서 접합부·투명도·타이밍·루프를 확인한다.
- 실제 표시 크기에서는 동작이 읽히고 자연스러워야 하며, 원본 해상도에서는 의도하지 않은 크기·윤곽·기준점 차이와 이음매가 없어야 한다. 본·파츠 개수나 고정 픽셀 검사만으로 완료 처리하지 않는다.
