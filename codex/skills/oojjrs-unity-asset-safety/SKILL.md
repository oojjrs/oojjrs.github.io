# oojjrs Unity Asset Safety

Use this skill for general Unity asset work under `Assets`, `Packages`, or project design-asset folders when no more-specific primary domain applies.

## Hard Rules

1. Codex must not create or modify Unity `.meta` files.
2. A `.meta` file corresponding to an in-scope asset is part of the same requested scope. Preserve or move an existing one with its asset. When staging or committing that asset is explicitly authorized, include a user- or Unity-generated in-scope `.meta` file in the same authorized scope even when Git reports it as new or untracked. Exclude only unrelated out-of-scope `.meta` files.
3. If an expected corresponding `.meta` file is absent, stop before commit or push and let the user or Unity generate it.
4. Put all temporary and intermediate files under a literal `$Trash` folder.
5. Keep generated candidates separate from final project assets until the user accepts them or the task clearly asks to install them.
6. Preserve unrelated dirty Unity files. Do not normalize or rewrite broad asset trees.

## Asset Workflow

1. If `Design.html` exists and the asset affects planning state, read it and plan a matching update.
2. Find existing assets, dimensions, naming, and references before creating replacements.
3. Before creating a Unity UI asset or recommending its size, inspect the target project's actual Canvas size and, when applicable, its `Canvas Scaler` reference resolution. Never assume FHD, QHD, or 4K; evaluate the intended placement at the project's scale, base source pixel dimensions and size recommendations on those project-specific values, and ask for them rather than guessing when they cannot be verified.
4. If the task becomes generated raster art, route to `$oojjrs-image-first-art-workflow` as the primary domain instead of stacking both skills.
5. When replacing a tracked asset, preserve the original file name only if existing references depend on it; otherwise update references deliberately.
6. When asset references change, validate only those references with exact path or GUID searches.

## Checks

Before finishing, check only the applicable changed asset properties:

- Codex did not create or modify `.meta` files.
- Every in-scope `.meta` file, including one generated by the user or Unity that Git reports as new or untracked, accompanies its corresponding asset; only unrelated out-of-scope `.meta` files are excluded.
- Before a requested commit or push, no asset that expects a corresponding `.meta` file is included while that file is absent.
- When UI dimensions or size recommendations changed, they use the verified project Canvas size and, when applicable, its `Canvas Scaler` reference resolution rather than an assumed FHD, QHD, or 4K Canvas.
- New temporary files are only under `$Trash`.
- Changed files match the requested asset scope.
