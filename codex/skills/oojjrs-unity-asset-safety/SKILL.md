# oojjrs Unity Asset Safety

Use this skill for Unity asset work before touching files under `Assets`, `Packages`, or project design-asset folders.

## Hard Rules

1. Codex must not create or modify Unity `.meta` files.
2. A `.meta` file corresponding to an in-scope asset is part of the same requested scope. Preserve or move an existing one with its asset, and stage and commit one generated by the user or Unity even when Git reports it as new or untracked. Exclude only unrelated out-of-scope `.meta` files.
3. If an expected corresponding `.meta` file is absent, stop before commit or push and let the user or Unity generate it.
4. Put all temporary and intermediate files under a literal `$Trash` folder.
5. Keep generated candidates separate from final project assets until the user accepts them or the task clearly asks to install them.
6. Preserve unrelated dirty Unity files. Do not normalize or rewrite broad asset trees.

## Asset Workflow

1. Read `$oojjrs-guidelines`.
2. Inspect `git status --short --branch` and identify unrelated dirty files.
3. If `Design.html` exists and the asset affects planning state, read it and plan a matching update.
4. Find existing assets, dimensions, naming, and references before creating replacements.
5. Before creating a Unity UI asset or recommending its size, inspect the target project's actual Canvas size and, when applicable, its `Canvas Scaler` reference resolution. Never assume FHD, QHD, or 4K; evaluate the intended placement at the project's scale, base source pixel dimensions and size recommendations on those project-specific values, and ask for them rather than guessing when they cannot be verified.
6. For image/art assets, use `$oojjrs-image-first-art-workflow` for the first visual pass and post-process only accepted outputs.
7. When replacing a tracked asset, preserve the original file name only if existing references depend on it; otherwise update references deliberately.
8. Validate local references with exact path/GUID searches where possible.

## Checks

Before finishing, verify:

- Codex did not create or modify `.meta` files.
- Every in-scope `.meta` file, including one generated by the user or Unity that Git reports as new or untracked, accompanies its corresponding asset; only unrelated out-of-scope `.meta` files are excluded.
- No asset that expects a corresponding `.meta` file is committed or pushed while that file is absent.
- Unity UI asset dimensions and size recommendations are based on the verified project Canvas size and, when applicable, its `Canvas Scaler` reference resolution rather than an assumed FHD, QHD, or 4K Canvas.
- Temporary files are only under `$Trash`.
- Changed files match the requested asset scope.
- `git diff --check` is clean for touched text assets.
