## Plan

`plan.json` contains `BatchId`, `AuthorizedSubmissions`, `LegacyListenPath` and `Conditions`. A default root daily page requires a batch ID ending in `yyyyMMdd`. Preserve the existing ID when appending.

Each condition supplies these fields:

| Field | Meaning |
| --- | --- |
| `Round`, `Title`, `OutputDirectory` | Unused round number, display title, directory containing its result |
| `Role`, `Genre`, `Energy` | Requested purpose and musical direction, without claiming a listening judgment |
| `SituationTags`, `SituationAssessment` | Array of requested tags and whether their fit has been assessed |
| `InputMode`, `Instrumental` | Actual submitted provider settings |
| `Prompt`, `SubmittedStyle` | Exact submitted prompt and separately submitted style, empty when the style field was disabled |
| `OriginalPrompt`, `OriginalStyle` | Original brief when comparing variants; these are not necessarily the submitted fields |

Optional confirmed provenance includes the date, selected model, actual submissions, credits and user assessments. Appending adds conditions and updates confirmed totals without replacing earlier records.

## Round Result

Each condition's `result.json` contains `DiscoveredCount`, `DownloadedCount`, `FailedCount`, `UnresolvedCount` and `Results`. The existing AMG builder expects two discovered results and zero unresolved results when no `round-state.json` exists. If a state file exists, the builder accepts only `Phase: complete`.

Each downloaded song needs `Id`, `Version`, `Status: downloaded`, `Title`, `Path`, `MeasuredDurationSeconds` and `DurationMeasurement`. Keep provider estimates separate from the decoded duration.

```json
{
  "MeasuredDurationSeconds": 112.44,
  "DurationMeasurement": {
    "method": "decoded-audio-samples",
    "tool": "ffprobe",
    "sampleRate": 48000,
    "decodedSamples": 5397120
  }
}
```

For a single audio stream, obtain decoded frame sample counts with:

```powershell
ffprobe -v error -select_streams a:0 -show_frames -show_entries stream=sample_rate:frame=nb_samples -of json $audioPath
```

Sum the returned frames' `nb_samples`; divide by the returned stream's `sample_rate`. Do not substitute the provider's `Duration` field or `format.duration`. Other audio layouts need an equivalent decoded measurement rather than an invented sample rate.

## Existing Builder and Player

```powershell
pwsh -NoProfile -File (Join-Path $storeRoot 'scripts/Build-DailyListening.ps1') -BatchDirectory $batchRoot -Date $day -ListenPath $listenPath
```

The builder emits one-line `const tracks=...;` and `const batchId=...;` assignments. The storage API parses those lines to resolve valid song IDs; preserve their structure if editing a page manually. The page sets `window.BgmStoreListen` with `kind: daily`, `tracks`, `key` and `batchId` and uses the shared CSS and deferred JavaScript.

For a separate nested list, use only a separately approved exact display title when appending an entry with `batchId`, `title` and repository-relative `path` to the `batches` array in `data/listener-batches.json`. Do not replace the registry. Existing daily lists do not need a duplicate registration when their date-derived identity already resolves.

Stable track numbers belong to `data/listener-track-numbers.json`; the builder assigns them through the shared helper. Reuse the same page ID so later additions cannot renumber already rated songs.
