# 로그인된 세션으로 Steam 공지 게시

이 절차는 현재 규칙과 사용자 지시가 허용하는 브라우저 도구로만 실행한다. 스킬 자체는 CUA 금지 규칙의 예외나 게시 권한을 만들지 않는다. 브라우저가 이미 로그인되어 있으면 Steam Guard나 QR 로그인을 새로 요구하지 않는다. 공지 생성·복제·저장·번역·게시 허가는 새 문구나 교체 문구의 허가가 아니다. 공통 문서 작성 지침에 따라 각 언어의 정확한 제목·요약·본문과 위치를 별도로 사전 허가받고, 허가는 99% 거절된다고 전제해 반드시 필요한 경우에만 묻는다. 그 외에는 질문 없이 생략하며 허가 전에는 파일·복제 초안·편집기에 먼저 넣지 않는다.

## 시작과 복제

1. 사용 가능한 브라우저·탭 목록에서 Steam Partner 또는 Community 탭을 찾는다. 이전 성공 방식을 요청받았다면 해당 작업의 도구 기록에서 사용 브라우저, 탭 접근 방식, 저장·게시 성공 증거를 먼저 확인한다. 기존 로그인 세션의 존재를 확인하기 전에 별도 프로필을 만들지 않는다.
2. 허용된 기존 세션을 연결하고, 화면의 계정과 대상 앱을 확인한다. SteamCMD의 builder 계정으로 공지를 작성할 수 있다고 추정하지 않는다. 쿠키·토큰을 추출하거나 다른 프로필에 복사하지 않는다.
3. 앱 관리 화면의 `이벤트 및 공지 게시/관리`로 이동한다. 최신 관련 공지의 본문·언어·아트워크를 확인하고, 복제할 각 언어의 정확한 제목·요약·본문과 위치를 먼저 허가받은 다음 해당 공지의 `복제`를 누른다.
4. 복제 창에서 필요한 모든 언어를 선택하고 확인한다. 언어를 모두 유지할 때는 `모두 선택`을 사용할 수 있다. 새 편집 화면의 `비공개, 미게시` 상태를 확인한다. 복제 응답이 늦으면 현재 창·대화상자·탭을 확인하고, 중복 복제를 누르지 않는다.

## 다국어 입력 도구

`scripts/sync-announcement-locales.mjs`는 CUA가 제공하는 `tab.playwright`와 `tab.getAXState`만 사용한다. 새 브라우저 실행, 로그인, 직접 HTTP 요청, 숨겨진 앱 상태 접근, 저장·게시 기능은 없다. `Apply`는 입력 후 대조하고 `Verify`는 언어를 전환하며 현재 입력값만 대조한다. 불일치가 있으면 즉시 중단하고 현재 언어를 남긴다. 수정·재시도 전 현재 화면을 다시 확인한다.

아래 입력 자료와 별도 승인 기록을 준비하며, 프로젝트별 ID·이벤트·번역을 스크립트에 하드코딩하지 않는다. Apply의 마지막 인자인 textApproval에는 실제 사용자의 허가 지시 원문 userInstruction, 대상 editorUrl, 정확히 승인받은 localizations, 해당 언어의 languageValues와 입력 위치 bindings를 담는다. bindings의 languageSelect·languageIndex·title·summary·body가 승인 기록과 같아야 한다. 사용자의 실제 허가 후에만 이 기록을 도구 메모리에 만들며, 레코드나 플래그를 스스로 채우는 것으로 허가를 대신하지 않는다. 하나라도 누락되거나 문구·언어·위치·현재 편집기 주소가 다르면 Apply는 입력하지 않는다. Verify에는 승인 기록이 필요 없고 문구를 채우지 않는다. 선택적인 summary는 빈 문자열로 둘 수 있으며, 검사를 통과시키려고 요약 문구를 추가하지 않는다.

- 각 언어의 정확한 문구와 위치를 별도로 사전 승인받은 `localizations`: 각 항목에 `language`, `title`, `summary`, `body`가 있는 배열. 공지마다 지원 언어 전체를 포함한다.
- `languageValues`: 현재 편집기의 실제 언어 옵션 값과 locale 이름의 대응표. 이전 이벤트의 값은 참고로만 사용한다.
- `bindings`: 현재 DOM에서 확인한 언어 선택기, 제목·요약·본문의 고유 선택자와 현재 편집기에 표시된 글자 수 제한.

CUA REPL에서 현재 편집 화면을 읽은 뒤 모듈을 불러온다. 아래 선택자는 2026-10-18의 Mines 게시에서 확인한 예이므로, 새 세션에서는 현재 DOM과 일치하는지 먼저 확인한다. 제목·본문은 현재 표시되는 placeholder를 사용할 수도 있다. DOM과 다른 선택자를 추측해서 반복하지 않는다.

```javascript
var localeSync = await import('file:///D:/.codex/skills/oojjrs-steam-announcements/scripts/sync-announcement-locales.mjs');
var bindings = {
  languageSelect: 'select',
  languageIndex: 1,
  title: 'input.pr-SNhBIp0a0Q9WVTlyWy',
  summary: 'textarea._2eQap2-rzAvN6X1pV_WPaj',
  body: 'textarea.NENu2K19GJmLf1Asga-WF',
  titleLimit: 80,
  summaryLimit: 180
};
var result = await localeSync.syncAnnouncementLocales(tab, draft.localizations, languageValues, bindings, 'Apply', draft.textApproval);
nodeRepl.write(result.map(x => x.language));
```

모듈 경로는 실제 설치된 스킬 경로에 맞춘다. 입력 중 화면값 대조는 저장 증거가 아니다. 입력 완료 후 저장하고, 성공 알림과 생성된 이벤트 ID를 기록한다. 저장 후 새로 읽은 편집 화면에서 같은 도구의 `Verify`로 언어별 제목·요약·본문을 대조하면 저장 내용의 검증으로 사용할 수 있다.

## 빌드 연결과 공개

1. `빌드에 연결...`에서 의도한 브랜치와 현재 배포된 BuildID를 선택한다. 현재 목록의 role을 확인한다. React 선택 항목이 접근성 화면에는 버튼처럼 보이더라도 DOM에는 `option`일 수 있다. 선택 실패 시 실제 DOM을 읽고 수정하며 같은 실패 선택자를 반복하지 않는다.
2. 본문·요약의 사용자 수정사항, 지원 언어, 고정 안내와 마무리 문구, 아트워크, 연결 브랜치·BuildID를 확인하고 저장한다. 성공 알림을 확인한다.
3. `게시` 탭에서 공개 시점과 범위를 확인한다. 탭 이동 버튼과 실제 실행 버튼이 같은 이름일 수 있으므로 현재 영역을 확인한다. 새 공지는 `기존 이벤트로 교체`가 아닌 일반 게시를 사용한다.
4. 정확한 문구·위치와 게시가 각각 허가된 범위에서는 게시 지시의 중복 확인을 요구하지 않는다. 게시 허가로 미허가 문구를 작성하지 않는다. 경고가 나타나면 실제 내용을 읽는다. 일부 언어의 아트워크를 영어로 대체하는 기존 관례는 허용할 수 있지만 다른 경고를 같은 이유로 일괄 무시하지 않는다.
5. 최종 게시 확인을 실행한 뒤 `성공적으로 게시를 완료했습니다` 또는 공개 상태를 확인한다. 결과가 불명확하면 같은 이벤트를 읽고 중복 게시를 피한다.
6. 반환된 공개 URL에서 제목·본문·게시 시각을 확인하고 증빙을 저장한다. 10개 번역 입력을 영어 하나의 성공으로 대신하지 않는다. 완료 보고에는 실제 공개 링크와 검증한 언어 수를 포함한다.
