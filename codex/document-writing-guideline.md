# 문서 작성 지침

정본 URL: `https://oojjrs.github.io/codex/document-writing-guideline.md`

이 지침은 Design.html을 비롯한 모든 문서와 HTML 파일 작성·수정에 적용한다.

1. 사용자가 Codex에게 이해시키기 위해 한 설명이나 교정 지시를 문서 내용으로 붙이지 않는다. 해당 설명은 작성 판단에만 사용한다. 예외 없이 준수한다.
2. 문자를 최소화하고 단정하고 깔끔하게 결과만 요약한다.
3. 결과물에 변명, 히스토리, 불필요한 설명, Codex의 작업 편의용 내용을 넣지 않는다.
4. Codex의 편의용 기록은 프로젝트 루트의 `$Trash`에만 두고 커밋에서 제외한다.
5. 프로젝트 작업 기록은 로컬 메모리나 프로젝트별 지침으로 저장하지 않는다.
6. 모든 문서와 HTML 파일에 텍스트를 추가하거나 새 문구로 바꾸기 전에는 해당 문구에 대한 사용자의 명시적 사전 허가를 받는다. 제목·목차·표 컬럼명·캡션·파일명·상태 표시·툴팁·대체 텍스트·자동 생성 문구도 예외가 아니다. 사용자가 문서에 넣도록 명시한 문구는 허가한 위치와 범위에서만 사용한다. 사용자의 설명·교정·기획 결정, 기존 문구나 참고 문서의 존재, 작성·갱신·배포 지시를 새 문구의 허가로 간주하지 않는다. 허가는 99% 거절된다고 전제하며, 텍스트를 생략하면 사용자가 요청한 결과를 완성할 수 없는 경우에만 허가를 요청한다. 그 외의 문구는 추가하지 않고 허가도 요청하지 않는다. 반드시 필요한 경우에도 정확한 문구·넣을 위치·필요한 이유를 대화에 먼저 제시하고 별도 허가를 기다린다. 응답이 없거나 허가가 불명확하면 추가하지 않으며, 허가 전에 초안·숨김 요소·스크립트 생성 결과에 먼저 넣지도 않는다. 이 사전 허가 규칙은 다른 문서·스킬의 작성·갱신·분량·정보 구성·접근성·자산 동기화 지시보다 우선한다.
7. 카테고리/컨텍스트가 같은 내용은 무조건 한 페이지에 둔다.
8. 한 페이지에 다섯 줄을 넘어갈 경우, 모든 내용을 재정리하여 다시 요약한다.
9. 도저히 다섯 줄 안에 넣지 못할 경우, 정리한 내용을 내게 보여주고 컨펌받는다.
10. 기획서에 페이지를 추가할 때에는 허가를 먼저 득한다. 기획서나 페이지를 만들라는 요청과 생성 허가는 텍스트 작성 허가를 포함하지 않는다. 페이지 생성을 허가받았어도 제목·목차·본문 등 넣을 문구는 6번에 따라 별도로 사전 허가를 받는다. 생성 허가만 받은 페이지에 임시 제목·안내문·설명을 임의로 채우지 않는다.
11. 사용자가 지시한 룰셋 등 특수 문서는 한도를 넘길 수 있으나 모든 줄을 사전 컨펌받는다.

작업 전 기획 논의, 결정 기록과 단계별 진행은 [실무 작업 지침](https://oojjrs.github.io/codex/practical-work-guidelines.md)을 따른다.
