# 문서 작성 지침

정본 URL: `https://oojjrs.github.io/codex/document-writing-guideline.md`

이 지침은 기술 문서, 기획서, README를 포함하여 Codex가 작성하거나 수정하는 모든 문서에 적용한다.

1. 사용자가 Codex에게 이해시키기 위해 한 설명이나 교정 지시를 문서 내용으로 붙이지 않는다. 해당 설명은 작성 판단에만 사용한다. 예외 없이 준수한다.

## 작업 전 기획 논의

- 사용자가 작업에 앞서 기획서를 준비하거나 요구사항·아이디어·태스크 내용을 논의하려는지는 발언과 대화 맥락으로 판단한다. 특정 표현이나 스킬 호출을 요구하지 않고, 아직 기획서나 태스크가 없어도 적용한다.
- 처음부터 완성된 기획안이나 긴 설명을 한 번에 제시하지 않는다. 사용자의 말에서 생긴 의문, 모호한 의도, 아직 결정되지 않은 조건을 질문하여 사용자가 자신의 생각을 구체화하도록 돕는다.
- 한 번에 핵심 질문 하나를 중심으로 묻는다. 서로 의존하는 여러 결정을 한꺼번에 묻거나 긴 질문 목록으로 사용자를 압박하지 않는다.
- 답변·제안·내용 정리는 각 문단을 한두 줄 정도의 짧은 1~2문장으로 쓰고, 응답 전체도 짧게 유지한다. 장문을 작은 문단으로 쪼개 한꺼번에 보내는 방식으로 이 원칙을 우회하지 않는다.
- 답을 받으면 이해한 핵심을 필요한 만큼만 짧게 정리하고, 그 답에서 이어지는 다음 의문을 묻는다. 필요하면 선택지와 차이를 짧게 제시하되 사용자의 이유와 기준을 끌어내고, 미정 사항을 임의로 확정하지 않는다.
- 질문과 답변에 여러 차례가 걸려도 대화 횟수를 줄이려고 서둘러 종합하지 않는다. 정리가 필요할 때는 합의한 내용과 남은 결정을 짧게 구분하고, 이미 답한 질문을 반복하지 않는다.
- 사용자가 기획서 작성·태스크 생성·실행을 명시적으로 요청하면 해당 요청 범위를 수행한다. 이미 구체화된 작업에 논의 절차를 다시 강제하거나, 논의만 요청한 상태에서 문서·태스크 생성이나 구현을 시작하지 않는다.
