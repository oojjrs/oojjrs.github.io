# 문서 작성 지침

정본 URL: `https://oojjrs.github.io/codex/document-writing-guideline.md`

이 지침은 Design.html을 비롯한 모든 문서와 HTML 파일 작성·수정에 적용한다. 단, `CodexWorkMemory.md`에는 아래 4·5번의 예외를 적용한다.

1. 사용자가 Codex에게 이해시키기 위해 한 설명이나 교정 지시를 문서 내용으로 붙이지 않는다. 해당 설명은 작성 판단에만 사용한다. 예외 없이 준수한다.
2. 문자를 최소화하고 단정하고 깔끔하게 결과만 요약한다.
3. 결과물에 변명, 히스토리, 불필요한 설명, Codex의 작업 편의용 내용을 넣지 않는다.
4. 프로젝트 루트의 `CodexWorkMemory.md` 하나를 Codex 전용 작업 메모리로 사용한다. 사용자 발언·설명·교정, 모든 의사 결정과 이유, 제안·폐기안, 작업 경과·검증 근거·미해결 사항·다음 작업을 자유롭게 기록한다. 언어·형식·분량은 Codex가 정하며, 이 파일에는 문구 사전 허가·다섯 줄 제한·설명 및 작업 기록 금지를 적용하지 않는다. 프로젝트 작업을 시작하거나 재개할 때 현재 요약과 진행 상태부터 확인하고, 작업 중 갱신한다. 기존 기록을 임의로 지우지 않으며, 현재 사실과 과거 기록·추정을 구분한다.

   - 시작·재개 때는 현재 요약과 진행 상태부터 확인한다.
   - 새 요청이 과거 결정과 관련되면 해당 주제·파일·용어로 관련 기록을 검색하고 필요한 구간을 읽는다.
   - 이미 읽었고 바뀌지 않은 내용은 재사용하며, 요청마다 전체 파일을 반복해서 읽지 않는다.
   - 기억이 불확실하면 메모리와 현재 프로젝트를 확인한 뒤 판단한다.
   - 기록이 길어지면 Codex가 현재 요약과 색인을 관리하고 원래 기록을 보존한다. 사용자에게 읽을 위치나 시점 지정을 요구하지 않는다.
   - 새 기록에는 고유 식별자, 현재 시계에서 얻은 초 단위·시간대 포함 ISO 8601 기록 시각, 기록자, 원 발언자와 결정 주체를 남긴다. 사용자 발언·명시적 결정, Codex 제안·판단, 도구로 확인한 사실과 추정을 구분한다. 출처 스레드 ID와 확인 가능한 딥링크, 제공되는 턴·항목 ID, PC·작업자 식별 정보를 함께 기록하며 모르는 작성자나 출처를 만들어 넣지 않는다. 공개 제외 지시는 출처 기록에도 그대로 적용한다.
   - 기록 시각과 원 발언·사건 시각, 스레드 생성·갱신·활동 시각, 저장·가져오기 시각을 구분한다. 개별 발언 시각을 모르면 불명으로 남기고 확인 가능한 턴의 시각이나 구간을 별도 표시한다. 과거 시각을 추정해 채우거나 턴 시각을 발언 시각으로 바꾸지 않는다.
   - 최신성은 현재 요청의 명시적 확정·교정·철회, 기록 간 대체 관계와 현재 프로젝트의 확인 근거를 대조해 판단한다. 늦게 기록·가져왔거나 PC 시각이 더 크다는 이유만으로 기존 결정을 덮어쓰지 않는다. 목표 기획과 현재 구현을 구분하며, 다른 PC·작업자의 기록이 충돌하고 근거가 부족하면 미해결로 표시하고 관련 출처를 더 확인한다. 보지 못한 변경까지 최신으로 확인했다고 주장하지 않는다.
   - 결정 수정·철회는 원기록을 보존하면서 무엇을 대체하는지 기록 식별자나 정확한 출처로 연결하고 현재 유효·대체됨·철회·미해결 상태를 구분한다. 요약에는 마지막 확인 시각과 근거 기록을 남기며, 완료·실패·중단은 실제 확인 결과로 갱신한다. Codex의 보고나 예정된 작업을 검증된 사실·성공 결과로 기록하지 않는다.

5. `CodexWorkMemory.md`는 `$Trash` 밖의 프로젝트 루트에 보존한다. 저장소 사용은 필수가 아니며, 프로젝트가 저장소를 사용하는 경우 필요에 따라 관련 변경과 함께 저장소에 올릴 수 있다. Codex가 상황을 보고 저장소 반영을 제안할 수 있으나, 메모리 작성만으로 저장소 반영이나 게시를 허가받은 것은 아니다. 작업 커밋이 허가되면 해당 작업과 관련된 메모리 변경도 필요에 따라 별도 포함 허가 없이 함께 커밋할 수 있다. 메모리를 매번 커밋할 의무는 없으며, 무관하거나 범위가 불명확한 기록은 포함하지 않는다. 이 파일은 프로젝트 지침이나 현재 사실·사용자 승인의 정본이 아니다. 기록을 Design.html 등 다른 문서에 옮기려면 정확한 문구·위치·이유를 먼저 제시하고 사용자의 별도 명시적 사전 허가를 받는다. 허가는 99% 거절된다고 전제하며, 기록의 존재나 의사 결정 동의를 전재 허가로 간주하지 않는다.
6. 모든 문서와 HTML 파일에 텍스트를 추가하거나 새 문구로 바꾸기 전에는 해당 문구에 대한 사용자의 명시적 사전 허가를 받는다. 제목·목차·표 컬럼명·캡션·파일명·상태 표시·툴팁·대체 텍스트·자동 생성 문구도 예외가 아니다. 사용자가 문서에 넣도록 명시한 문구는 허가한 위치와 범위에서만 사용한다. 사용자의 설명·교정·기획 결정, 기존 문구나 참고 문서의 존재, 작성·갱신·배포 지시를 새 문구의 허가로 간주하지 않는다. 허가는 99% 거절된다고 전제하며, 텍스트를 생략하면 사용자가 요청한 결과를 완성할 수 없는 경우에만 허가를 요청한다. 그 외의 문구는 추가하지 않고 허가도 요청하지 않는다. 반드시 필요한 경우에도 정확한 문구·넣을 위치·필요한 이유를 대화에 먼저 제시하고 별도 허가를 기다린다. 응답이 없거나 허가가 불명확하면 추가하지 않으며, 허가 전에 초안·숨김 요소·스크립트 생성 결과에 먼저 넣지도 않는다. 이 사전 허가 규칙은 다른 문서·스킬의 작성·갱신·분량·정보 구성·접근성·자산 동기화 지시보다 우선한다.
7. 카테고리/컨텍스트가 같은 내용은 무조건 한 페이지에 둔다.
8. 한 페이지에 다섯 줄을 넘어갈 경우, 모든 내용을 재정리하여 다시 요약한다.
9. 도저히 다섯 줄 안에 넣지 못할 경우, 정리한 내용을 내게 보여주고 컨펌받는다.
10. 기획서에 페이지를 추가할 때에는 허가를 먼저 득한다. 기획서나 페이지를 만들라는 요청과 생성 허가는 텍스트 작성 허가를 포함하지 않는다. 페이지 생성을 허가받았어도 제목·목차·본문 등 넣을 문구는 6번에 따라 별도로 사전 허가를 받는다. 생성 허가만 받은 페이지에 임시 제목·안내문·설명을 임의로 채우지 않는다.
11. 사용자가 지시한 룰셋 등 특수 문서는 한도를 넘길 수 있으나 모든 줄을 사전 컨펌받는다.

작업 전 기획 논의, 결정 기록과 단계별 진행은 [실무 작업 지침](https://oojjrs.github.io/codex/practical-work-guidelines.md)을 따른다.
