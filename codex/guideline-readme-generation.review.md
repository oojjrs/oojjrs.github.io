# GitHub README.md Rules

Read this only for GitHub-facing `README.md` creation, review, cleanup, or update. Keep it tiny. The text-addition approval rule in the [document writing rules](https://oojjrs.github.io/codex/document-writing-guideline.md) takes precedence over every content or synchronization instruction below.

1. Write a `README.md` only when the repository needs a public-style entry point.
2. Keep it short. The items below are optional content choices, not a required outline or permission to fill missing sections, table columns, examples, or link labels. No filler, long introductions, marketing copy, or copied chat/planning text.
3. First run or use instructions should be one compact block: open solution/project, press F5, or the shortest package/reference step that applies.
4. For libraries, prefer a compact components table over prose. Suggested columns: Component, Kind, Purpose.
5. Include only what helps a first visitor judge or use the repository: name, one-line purpose, status/scope, components, minimal usage, and links.
6. Keep internal workflow, task queues, GitHub Project notes, agent rules, release chores, and design debates out of README.
7. Link deeper docs such as `Documentation~/`, `CHANGELOG.md`, API docs, or examples instead of duplicating them.
8. Preserve the existing README language unless the user asks to change it. Validate only changed links, commands, code snippets, and factual claims against their live project sources.
